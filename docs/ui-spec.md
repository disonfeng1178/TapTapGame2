> 项目：《旗令防线 Signal Line》｜ 平台：**TapTap 制造（全程）**｜ 分辨率基准：竖屏 3:4（1080×1440）
> 定稿日期：2026-09-27 ｜ 状态：可执行
> 配套：`docs/art-spec.md`（视觉）｜ `docs/audio-list.md`（听觉）｜ `docs/design-final.md` v6（机制）

---

## 0. 为什么这份文档必须手写

AI 能生成"一张好看的 UI 图"，但**生成不了"一套自洽的 UI 规范"**。游戏 UI 出问题的真正原因从不是某张图不好看，而是：
- 这个血条和那个蓝条粗细不一样
- 这个按钮和那个面板圆角不一样
- 禁用态和普通态只差 2% 灰度，弱视玩家看不出来
- 战斗中出现了一个常驻特效，挡住倒计时

**这份文档的唯一目的：把这些"不一样"提前定死，让后面无论谁做（人或 AI）都只能照抄。**

## 1. 屏幕分区（6 区，比例固定不可调）

```
┌─────────────────────────────┐ 0%
│ ① 顶栏 8%                   │  倒计时 · 波次 · 基地血
├─────────────────────────────┤ 8%
│                             │
│ ② 战场 37%                  │  3 路横线（敌右→左，基地在左）
│                             │  【只读·不可操作】
├─────────────────────────────┤ 45%
│ ③ 指挥条 7%                 │  军令条 · 变阵槽 · 阵图缩略
├─────────────────────────────┤ 52%
│ ④ 阵图 20%                  │  3×4 只读阵图（核心视觉）
│                             │  【只读·不可操作】
├─────────────────────────────┤ 72%
│ ⑤ 旗语栏 13%                │  旗槽(3色) · 手牌(6面) · 搓招键
├─────────────────────────────┤ 85%
│ ⑥ 战鼓区 15%                │  大鼓 · 连击 · 体力  ← 拇指区
└─────────────────────────────┘ 100%
```

### 拇指可达性检查（按操作频次分配）

| 区 | 操作频次 | 屏幕位置 | 可达性 | 结论 |
|---|---|---|---|---|
| ⑥ 战鼓 | **极高**（每秒数次） | 底部 | ✅ 拇指舒适区 | 正确 |
| ⑤ 旗语栏 | 中（每 20-40s 一次） | 中下 | ✅ 拇指可达 | 正确 |
| ①③④② | **零**（纯只读） | 顶部/中部 | 无需可达 | 正确 |

> **设计纪律：所有需要点的控件必须在下方 40% 屏幕内。** 顶部只放"看"的东西，不放"点"的东西。

### 竖屏安全区

| 边 | 距离 | 用途 |
|---|---|---|
| 上 | 8% | **不可放关键信息**（刘海/状态栏） |
| 下 | 12% | **不可放关键信息**（系统手势区）——战鼓区需上移 |
| 左 | 4% | 边缘留白 |

**设计基准统一为 1080 宽的百分比，不给绝对像素。**

## 3. 组件状态表（**核心：AI 最缺的就是这部分**）

### 3.1 军令条（组件 5）

| 状态 | 触发条件 | 表现 | 数值 |
|---|---|---|---|
| 正常 | 0 < 军令 < 200 | 令金色填充 | — |
| 空 | 军令 = 0 | 填充空 + 条体脉动 1 次 | 60 军令/次 |
| 满 | 军令 ≥ 200 | 填充满 + 边缘金色描边闪烁 | **溢出作废**（必须明示） |
| 不足 | 点击变阵时 军令 < 费用 | 条体转赤缨色 + 抖动 | 搓招 60 / 点选 80 |
| 读条中 | 正在发动阵型 | 变阵槽进度环 | 2s / 4s |

**⚠️ 溢出作废必须显性告知玩家。** 建议：满时军令条上方浮出小字「已满 · 溢出浪费」持续 1s。这是 v6 最容易被误解的机制。

### 3.2 旗槽（组件 9）

| 状态 | 表现 |
|---|---|
| 有货 | 数字高亮 + 旗色描边 |
| 零库存 | 数字灰化（`#4A5568`） |
| 溢出 | 手牌满 6 面时，旗槽上方显示「溢出 → 10 军令/面」 |

### 3.3 手牌（组件 10）

| 状态 | 触发 | 表现 |
|---|---|---|
| 正常 | < 6 面 | 6 槽位，未满槽位空心 |
| 满 | = 6 面 | 满槽位实心 + 顶部「6/6」 |
| 溢出 | 获得第 7 面 | 顶部红色闪「溢出 +10 军令」 |
| 即将溢出击破 | 5/6 时 | 顶部橙色「再得 1 面将溢出」 |

### 3.4 变阵槽（组件 6）

| 状态 | 触发条件 | 表现 | 说明 |
|---|---|---|---|
| 空 | 未发令 | 虚线轮廓 + 「+」 | — |
| 生效中 | 阵型 20s 已在 | 实心 + **倒计时环** | 完美判定 26s |
| 真空期 | 刚换阵 0-3s | 灰化 + 「重整中」 | 无 buff |
| 读条 | 搓招成功 2s / 神令 4s | 进度环 + **全屏压暗 15%** | **期间大鼓不可点** |
| 不可用 | 军令或旗不足 | 灰化 + 费用数字红显 | — |

### 3.5 连击计（组件 14）

| 状态 | 阈值 | 表现 | 音效 |
|---|---|---|---|
| 静默 | ×1-24 | 数字常态 | 单鼓 |
| 加密 | ×25 | 数字放大 1.1× + 描边亮起 | 重鼓 |
| 强 | ×50 | 数字 1.2× + 底部光带 | 重鼓 + 加密层 |
| 满 | ×100 | 数字 1.3× + 全屏边框脉冲 | 齐吼 |
| 断 | 窗口 5s 未击鼓 | 数字灰化下滑消失 | 闷响 |

> **断连击的反馈必须明确。** 玩家会因误操作断掉，必须立刻知道"我刚才攒的没了"——这是本作最敏感的体验点。

### 3.6 体力条（组件 15）

| 状态 | 表现 | 说明 |
|---|---|---|
| 充足 | 常态 | 上限 200 |
| 偏低 | < 60 时转赤缨色 | **背水一战的解锁条件之一** |
| 空 | 归零 + 大鼓变暗 | 此时击鼓出 `sfx_drum_empty` |

> **背水按钮在体力 ≥ 60 时显示为禁用态并提示「需体力 <60」** ——这是 v6 修正 ② 的核心反馈，必须明示。

### 3.7 搓招区（组件 11/12）

| 状态 | 表现 |
|---|---|
| 空闲 | 三色按键常态，已按序列显示为空 |
| 输入中 | 已按键位高亮，序列文本实时更新（如「红 蓝 _」） |
| 成功 | 全序列闪白 + 环出完美标识（若 4s 内无错） |
| 错误 | 序列区转赤缨 + 抖动 2 次（**不扣资源**，只断连击） |
| 锁定 | 读条期间全部按键变暗 |

**键盘位置**：三色键横向排列于 ⑤ 区底部，间距 ≥ 96px（1080 宽基准），保证拇指不误触。

## 4. 视觉规范（引用 `art-spec.md`，此处只列 UI 相关）

### 4.1 字号阶梯（1080 宽基准，共 6 级）

| 级别 | 字号 | 字重 | 用途 |
|---|---|---|---|
| Display | 72px | Bold | 倒计时最后 10 秒 |
| H1 | 52px | Bold | 结算页总分、阵型名 |
| H2 | 40px | Bold | 区域标题、当前阵型 |
| Body | 32px | Regular | 伤害飘字、说明文字 |
| Label | 26px | Medium | 费用数字、旗数 |
| Caption | 20px | Regular | 提示语、教程文字 |

**⚠️ 纪律：不存在第 7 级。** 需要更小的信息 = 该信息不该存在。
**验收标准**：截图缩到 390px 宽（手机实际显示），Caption 级别仍 ≥ 9px 可读。

### 4.2 圆角与描边

| 元素 | 圆角 | 描边 |
|---|---|---|
| 面板 / 弹出层 | 24px | 2px `#1C2230` |
| 按钮 | 16px | 2px |
| 军令条 / 体力条 | 999px（胶囊） | 2px |
| 旗面 / 卡片 | 12px | 2px |
| 小兵（阵图内） | 圆形 | 3px 提亮 20% |

> **全部圆角只有 4 档、描边只有 2 档 + 1 档强调。** 这就是"设计系统"的全部内容。

### 4.3 动效时长表（UI 部分）

| 动作 | 时长 | 缓动 |
|---|---|---|
| 按钮按下 | 0.06s | 无（要"硬"） |
| 面板弹出 | 0.25s | ease-out-back |
| 数字变化（军令/血） | 0.20s | ease-out（**必须补间，不能瞬跳**） |
| 阵型切换（12 单位错峰） | 0.30s | ease-out-back |
| 波次预警横幅 | 0.80s | 右滑入 |
| 背水按钮浮现 | 0.15s | 缩放 0.8→1.0 |

## 5. 首次进入的视线引导（关系到「有效试玩 ≥50」）

3 分钟试玩者的注意力必须在 20 秒内被抓住。**引导顺序即信息优先级：**

| 秒 | 引导 | 手段 |
|---|---|---|
| 0-3 | 看到战场在打，敌人在动 | 无引导（战场自动进行） |
| 3-6 | **指向大鼓** | 大鼓呼吸高亮 + 手指动画 + 「连打」文字 |
| 6-10 | 玩家敲鼓 → 军令条涨 | 军令条首次填满时闪一次 + 「军令」文字 |
| 10-15 | 指向旗槽 + 搓招键 | 「搓出旗语」文字 + 旗槽高亮 |
| 15-22 | **强制一次成功搓招**（降低难度：单色阵、预填序列提示） | 高亮正确的两个键 |
| 22-28 | 阵型生效，阵图单位移动 | 阵图描边高亮 + 「变阵」文字 |
| 28-40 | 玩家理解"我能靠打鼓 + 旗语改变战局" | — |

> ⚠️ **第 15-22 步的"强制成功搓招"是刻意的**。第一次搓招失败会直接把玩家赶走（因为错误会断连击）。先给一次成功体验，再引入难度。

## 6. TapTap 制造实现要点

| 要点 | 说明 |
|---|---|
| **不支持 JavaScript** | 引擎为 Lua/C# 系（UrhoX）。所有逻辑与 UI 绑定须在平台支持的语言里实现 |
| 布局系统 | **Yoga Flexbox** + **NanoVG 矢量渲染**，40+ 内置控件，官方自评 UI/HUD 能力 9/10 |
| 资产导入 | 素材库支持图片、音频、**Spine 3.8-4.2 骨骼动画**、文件夹批量上传 |
| ⚠️ **第一张地图决定全局 UI/UX 风格** | 社区避坑帖明确：不符预期要果断重建项目。→ **第一版 UI 不许赶工，但也别将就** |
| ⚠️ 「UI 效果图转实际组件」有折腾过程 | 社区教程证实需 PS 基础。→ 本文档已把规格定死到"可直接编码"，跳过效果图环节 |
| 本地开发模式 | 走 Maker MCP，可与 AI 编程助手配合；可先浏览器工作区，后期切本地 |
| 导出 | 内置构建 + 预览 + 发布到 TapTap（自动生成图标/截图/宣传图） |

## 7. 自检清单（实现完成后逐条打勾）

- [ ] 截图缩到 390px 宽，所有文字仍可读（Caption ≥ 9px）
- [ ] 截图转灰度，仍能分清我方/敌方（形状而非颜色）
- [ ] 顶部 8% / 底部 12% 无关键信息
- [ ] 军令满时明确提示"溢出浪费"
- [ ] 背水按钮在体力 ≥ 60 时显示禁用 + 原因
- [ ] 断连击有明确反馈
- [ ] 搓招错误**不扣资源**（只断连击），且有视觉提示
- [ ] 数字变化是补间的，不瞬跳
- [ ] 读条期间大鼓不可点，且有视觉明示
- [ ] 首次进入 40 秒引导可完整走通
- [ ] 同时播放的动画类型 ≤ 4 种
- [ ] 30 只蜂群 + 15 击特效同屏 ≥ 60fps（**未验证，最高风险项**）
